# 文書レビュー

対象文書: $ARGUMENTS（未指定の場合は docs/ 配下の全文書を対象とする）

Agent ツールで subagent_type: doc-reviewer を起動し、対象文書のレビューを依頼する。

## なぜサブエージェントか

文書レビューは大量のファイルを読み込むため、メインの会話コンテキストで行うと文脈が文書内容で埋まってしまう。doc-reviewer は**隔離されたコンテキスト**でレビューを実施し、結論だけを返すため、メインの文脈を汚さずに済む。レビュー本体を自分で行わず、必ずサブエージェントに委譲すること。

## 依頼内容

doc-reviewer への依頼には以下を含める。

- 対象文書のパス（$ARGUMENTS、未指定なら docs/ 全体。docs/ideas/ の構想メモは草稿のためレビュー対象から除外してよい）
- 観点: 記述の正確性（ソースコード・テストとの整合）、文書間の矛盾、用語集との用語不一致、古くなった記述、欠落している情報
- 出力: 指摘ごとに「対象ファイル・該当箇所・問題・修正案」の形式で報告すること

## 報告の要約

サブエージェントの報告を受けたら、次の形式でユーザーに要約する。

1. **重大な指摘**（内容が誤っている・実装と矛盾している）
2. **改善提案**（表現・構成・用語統一）
3. **問題なしと確認された文書**

修正の実施はこのコマンドの範囲外とする。ユーザーが修正を指示した場合にのみ着手する。
