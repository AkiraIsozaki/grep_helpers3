# コードレビューの依頼

コードレビュアーのサブエージェントを起動し、問題が波及する前に検出する。レビュアーには**セッション履歴を渡さず**、精密に構成した文脈だけを渡す。レビュアーは作業成果物に集中でき、自分の文脈も温存できる。

**基本原則:** 早くレビューし、頻繁にレビューする。

## レビューを依頼するタイミング

**必須:**
- サブエージェント駆動開発の各タスク完了後
- 主要機能の実装完了後
- main へのマージ前

**任意だが有効:**
- 行き詰まったとき（新鮮な視点）
- リファクタリング前（ベースライン確認）
- 複雑なバグ修正後

## 依頼手順

**1. git SHA を取得する:**
```bash
BASE_SHA=$(git rev-parse HEAD~1)  # または origin/main
HEAD_SHA=$(git rev-parse HEAD)
```

**2. レビュアーサブエージェントを起動する:**

Agent ツールで `code-reviewer` サブエージェント（`.claude/agents/code-reviewer.md` に定義）を起動する。依頼プロンプトには次の4点を**必ず**含める（欠けているとレビュアーは開始せず要求してくる）:

- **変更概要** — 何を実装したかの簡潔な要約
- **要求・計画** — 何をすべきだったか（計画ファイルのパス、タスク本文、要求事項）
- **BASE_SHA** — 開始コミット
- **HEAD_SHA** — 終了コミット

**3. フィードバックに対応する:**
- **Critical** — 即時修正
- **Important** — 先へ進む前に修正
- **Minor** — 記録して後日対応
- レビュアーが間違っていれば、技術的根拠を示して反論する

## 例

```
[タスク2「検証関数の追加」を完了した直後]

You: 先へ進む前にコードレビューを依頼する。

BASE_SHA=$(git log --oneline | grep "タスク1" | head -1 | awk '{print $1}')
HEAD_SHA=$(git rev-parse HEAD)

[code-reviewer サブエージェントを起動]
  変更概要: verify_index() と repair_index() を追加（4種の問題を検出）
  要求・計画: .steering/20260725-deployment/tasklist.md のタスク2
  BASE_SHA: a7981ec
  HEAD_SHA: 3df7661

[サブエージェントの返答]:
  Strengths: 構成が明快、実挙動を検証するテスト
  Issues:
    Important: 進捗表示の欠落
    Minor: 報告間隔のマジックナンバー (100)
  Assessment: 修正すれば先へ進める

You: [進捗表示を修正]
[タスク3へ]
```

## ワークフローとの統合

- **サブエージェント駆動開発:** 各タスク後にレビュー。問題が複合する前に検出し、次のタスクへ進む前に修正する。
- **計画の実行:** 各タスク後、または自然な区切りごとにレビューし、反映して続行する。
- **アドホック開発:** マージ前と行き詰まったときにレビューする。

## Red Flags

**決してしないこと:**
- 「単純だから」を理由にレビューを飛ばす
- Critical 指摘の無視
- Important 指摘を未修正のまま先へ進む
- 妥当な技術的指摘への言い争い

**レビュアーが間違っている場合:**
- 技術的根拠を添えて反論する
- 動作を証明するコード・テストを示す
- 不明瞭なら明確化を求める

レビュー観点・出力形式の定義: `.claude/agents/code-reviewer.md`
