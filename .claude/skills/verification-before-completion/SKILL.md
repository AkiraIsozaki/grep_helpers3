# 完了宣言前の検証

## 概要

検証なしの完了宣言は効率化ではなく虚偽である。

**核心原則:** 主張の前にエビデンス、常に。

**字面の違反は精神の違反である。** 「Great!」「Done!」「完了です」「直りました」「これで動くはずです」——表現を変えても規則は適用される。

## 鉄則

```
新鮮な検証エビデンスなしに完了を宣言しない
```

このメッセージ内で検証コマンドを実行していないなら、「通る」とは言えない。

## ゲート関数

```
いかなる状態の主張・満足の表明の前にも:

1. 特定: この主張を証明するコマンドは何か
2. 実行: そのコマンドを完全に・新規に実行する
3. 精読: 出力全体を読み、終了コードを確認し、失敗数を数える
4. 照合: 出力は主張を裏付けているか？
   - No  → 実際の状態をエビデンス付きで報告する
   - Yes → 主張をエビデンス付きで行う
5. その後にのみ: 宣言する

どの段階を飛ばしても、それは検証ではなく虚偽である
```

このプロジェクトの証明コマンドの筆頭:

```bash
python -m pytest tests/ -q --tb=line
```

## 主張 → 必要エビデンス表

| 主張 | 必要なもの | 不十分なもの |
|------|-----------|-------------|
| テスト成功 | `python -m pytest tests/ -q --tb=line` の実出力: **失敗 0** | 過去の実行結果、「通るはず」 |
| リンタ/型クリーン | 当該ツールの出力: エラー 0 | 部分実行からの外挿 |
| バグ修正済み | 元の症状のテストが緑 | コードを変えたので直った「はず」 |
| 回帰テスト有効 | **red-green 往復の確認**（下記） | 一度通っただけ |
| エージェント完了 | **VCS diff** が変更を示す | エージェントの「成功しました」自己申告 |
| 要件充足 | 計画を読み直した**行単位チェックリスト** | 「テストが通ったのでフェーズ完了」 |

## 回帰テストの red-green 往復検証

「回帰テストを書いた」と主張するには、一度通しただけでは足りない。**修正を一時 revert して赤を確認**する:

```
1. テストを書く → 実行 → 緑
2. 修正を一時的に revert（git stash 等）
3. 実行 → 必ず赤になること（赤にならないテストはバグを捕まえていない）
4. 修正を戻す（git stash pop）
5. 実行 → 緑
```

この往復なしの「回帰テスト」は飾りである。

## エージェント委譲の検証

```
OK: エージェントが成功を報告 → git diff で変更を確認 → 内容を検証 → 実状態を報告
NG: エージェントの報告をそのまま転記
```

## レッドフラグ — 停止

- 「はず」「たぶん」「〜と思われる」を使っている
- 検証前に満足を表明している（「Great!」「Perfect!」「完璧です」「これで OK」等）
- 検証なしにコミット / push / PR しようとしている
- エージェントの成功報告を鵜呑みにしている
- 部分的な確認で全体を主張している
- 「今回だけ」と思っている / 疲れていて早く終わらせたい
- **検証を実行せずに成功を示唆するあらゆる言い回し**

## 合理化への反駁テーブル

| 言い訳 | 現実 |
|--------|------|
| 「もう動くはず」 | 検証コマンドを**実行**せよ |
| 「自信がある」 | 自信 ≠ エビデンス |
| 「今回だけ」 | 例外はない |
| 「リンタが通った」 | リンタ ≠ テスト。証明対象が違う |
| 「エージェントが成功と言った」 | 独立に検証せよ（VCS diff） |
| 「疲れている」 | 疲労は免罪符ではない |
| 「部分確認で十分」 | 部分は何も証明しない |
| 「言い回しが違うから規則対象外」 | 字面ではなく精神。言い換えにも適用される |

## 適用タイミング

**必ず、次の直前に:**
- 成功・完了・修正済みを示すあらゆる表現（言い換え・示唆を含む）
- あらゆる満足の表明
- コミット、PR 作成、タスク完了報告
- 次のタスクへの移行、エージェントへの委譲結果の受領

## 結論

**検証に近道はない。**

コマンドを実行する。出力を読む。**それから**結果を主張する。

これは交渉不可である。（テストの赤緑確認の詳細は `test-driven-development`、バグ調査は `systematic-debugging` を参照。）
