# 用語集作成スキル

このスキルは、プロジェクト固有の用語と技術用語を体系的に定義するための詳細ガイドです。

## 前提条件

用語集作成を開始する前に、以下を確認してください:

### 推奨ドキュメント

1. **docs/product-requirements.md** (PRD)
2. **docs/functional-design.md** (機能設計書)
3. **docs/architecture.md** (アーキテクチャ設計書)
4. **docs/repository-structure.md** (リポジトリ構造)

用語集は、全てのドキュメントで使用される用語を統一的に定義します。
各ドキュメントから用語を抽出し、体系的に整理してください。

## 既存ドキュメントの優先順位

**重要**: `docs/glossary.md` に既存の用語集がある場合、
以下の優先順位に従ってください:

1. **既存の用語集 (`docs/glossary.md`)** - 最優先
   - プロジェクト固有の用語定義が記載されている
   - このスキルのガイドより優先する

2. **このスキルのガイド** - 参考資料
   - 汎用的なテンプレートと例
   - 既存用語集がない場合、または補足として使用

**新規作成時**: このスキルのテンプレートとガイドを参照
**更新時**: 既存用語集の構造と内容を維持しながら更新

## 出力先

作成した用語集は以下に保存してください:

```
docs/glossary.md
```

## 運用の規律（会話中の用語管理）

用語集は「あとでまとめて書く」ドキュメントではなく、会話・設計の中で能動的に育てるものです。以下の規律を守ってください:

### 1. 随時反映する（バッチしない）

会話の中で用語の定義が確定したら、**その場で** `docs/glossary.md` に反映します。複数の用語をため込んで後で一括更新する運用はしません。定義が確定した瞬間が、最も文脈が鮮明な瞬間です。

### 2. 曖昧な用語を放置しない

- 多義的・曖昧な用語が出てきたら、その場で問い直して定義を研ぎ澄まします（例:「その『アカウント』は利用者のことですか、認証主体のことですか?」）
- ユーザーが既存の用語集の定義と矛盾する使い方をしたら、即座に指摘します（例:「用語集では『キャンセル』をXと定義していますが、今はYの意味で使っていませんか?」）
- 用語の境界が曖昧なときは、境界を突く具体的なシナリオを挙げて定義を精密化します

### 3. コード実態と突き合わせて検証する

用語に関する主張（「〜は〜である」「〜のときは〜になる」）は、`src/` 配下のコード実態と照合して検証します。矛盾を見つけたら表面化させます（例:「用語集の定義ではXですが、コードはYの挙動になっています。どちらが正ですか?」）。正しい側に合わせて、用語集またはコード理解を更新します。

### 4. 用語集に実装詳細を書き込まない

用語集は用語の定義に徹します。実装手順・作業メモ・設計判断の置き場ではありません（作業単位の記録は `steering` スキルが管理する `.steering/` に置きます）。
