えー、この長屋にひとり、鼻つまみ者がございました。あだ名を**らくだ**——本名を
「**規律なしの AI 運用**」てえまして、こいつがまあ乱暴者だ。設計も見せずに鑿を振り回す、
テストは書かねえ、根本原因も調べずに継ぎを当てる、挙句「できやした」と言った仕事が
検分してみりゃボロボロ。長屋じゅう、こいつの通った後は普請がガタガタでございます。

そのらくだが、ある朝ぽっくり死んだ。死因は**食あたり**——フラットな `.md` てえやつを
食らいましてね、こいつがどうにも消化できねえ。なにせフラットな `.md` は
**スキルとして読み込まれねえ**。看板だけ出して中身は留守、栄養がまるで回らねえまま、
あえなく往生と相成りました。

そこへ乗り込んできたのが兄貴分の**半次**。ちょうど木戸の前を、気の弱い**屑屋の久六**が
「くずーい、屑屋でございー」と通りかかる。

半次「おう屑屋! ちょいと面ぁ貸しな」

久六「へ、へい……あっしぁ商いの途中で」

半次「らくだが死んだ。**弔いを出す**。手前、帳面つけるくれえできるだろう。
古い運用を仕舞って、新しい仕込み部屋を建てる。その次第を残らず書き留めるんだ」

久六「へい……逆らうと、その」

半次「察しがいいね。逆らってみろ、**死人にかんかんのうを踊らせる**——
規律なしの AI をもういっぺん野に放って、手前のコードベースで踊らせてやろうか」

久六「ひぇっ! 書きます書きます!」

てなわけで、これより久六の帳面でございます。

## 香典帳 — skills 一覧（19本）

半次「香典を集めてきた。三軒回ってな——**本家 spec-driven、分家 superpowers、
出入りの skills-main**。包みの厚い順もこの順だ。帳面には項目別につけろ」

### プロジェクト規約 — この長屋の家訓

| スキル | 内容 |
|---|---|
| `coding-conventions` | 日本語コメント・命名規約・構造規約・実装の罠。コード作成/編集時に必ず適用 |
| `writing-tests` | テスト5層の縄張り・モックの線引き・日本語テスト名。テスト作成/修正時に必ず適用 |

久六「これぁ元からうちにあった分で……らくだの野郎、**一度も読まなかった**やつだ」

半次「読まなかったんじゃねえ、**読めなかった**のよ。フラットな `.md` は読み込まれねえ。
今度からは `<name>/SKILL.md` の形で、ちゃあんと膳に載る」

### 開発規律 — 分家 superpowers の香典。これが効くんだ

| スキル | 鉄則 |
|---|---|
| `brainstorming` | 設計を見せて旦那の承認をもらうまで鑿は握らせねえ（ハードゲート） |
| `test-driven-development` | 失敗するテストなしにプロダクションコードを書くな。先に書いちまったら削除だ |
| `systematic-debugging` | 根本原因も調べずに直すな。三度しくじったら手を止めて骨組みを疑え |
| `verification-before-completion` | 新鮮な検証エビデンスなしに「できやした」と言うんじゃねえ |
| `requesting-code-review` | タスク完了・マージ前にゃ code-reviewer に検分を頼め |
| `receiving-code-review` | 指摘は検証してから直せ。「おっしゃる通りで!」なんて太鼓持ちは御法度 |

久六「……兄貴、この六本、まるっきり**らくだの叱られ帳**じゃござんせんか。
設計見せねえ、テスト書かねえ、調べずに直す、できやしたの嘘、検分嫌い」

半次「そうよ。**あいつのしくじりを一本ずつ裏返すと、この表になる**。
よくできた香典だろう」

## 離れの検査役 — agents 一覧（3体）

半次「検分は離れ座敷の三人にやらせる。手前の仕事に手前で判をつくのは、
らくだの『できやした』と同じ穴よ。だから**履歴を知らねえ他人**に、
**刃物を取り上げた上で**診させる」

| agent | 役割 | ツール |
|---|---|---|
| `code-reviewer` | 変更差分の2軸レビュー（Standards=規約準拠 / Spec=要求一致）、重大度付き | 読取 + git |
| `doc-reviewer` | 文書の5軸評価（完全性・明確性・一貫性・実装可能性・測定可能性） | 読取のみ |
| `implementation-validator` | 静的検証（層分離・可視性・docstring 形式・テスト縄張り）。コードは実行しねえ | 読取 + grep |

| コマンド | 流れ |
|---|---|
| `/setup-project` | docs/ideas/ の構想メモ → 文書5種を順に生成（PRD のみ人間承認） |
| `/add-feature <名前>` | brainstorming（承認ゲート）→ steering 計画 → TDD で tasklist 消化 → 検証 → 振り返り |
| `/refactor <対象>` | steering 計画 → 9原則分析 → 原子サイクル実行 → 検証 |
| `/review-docs [パス]` | doc-reviewer に委譲（メインの座敷を汚さねえ） |

久六「どうでえ! 一分の隙もねえ! ついでにスキルを増やすときの作法も書いといてやらあ!」

1. まず `writing-skills` スキルを起動しな（形式・記法・検分のやり方が書いてある）
2. 形式は `skills/<name>/SKILL.md`。frontmatter は `name` / `description` のみ。description にゃ
   「**いつ使うか**」だけ書け（内容を要約してみろ、看板だけ読まれて中身が素通りされる）
3. 全て日本語だ。他スキルへの参照はプレーン名（`` `steering` スキル``）。`@` リンクは御法度
4. 増やしたら CLAUDE.md の案内板と本 README を揃えろ。案内板の古い長屋は道に迷うぜ

## 火屋まで — おなじみの幕切れ

さて夜も更けて、二人してらくだの亡骸——**旧運用の残骸**を樽に詰めまして、
火屋（ひや）、焼き場へと担いで参ります。フラットな `.md` の旧配置に、蔵入りの計画書の写し、
`superpowers:` の接頭辞のついた古い呼び名、そんなものを樽へ一切合切。

ところが途中の暗がりで樽の底が抜けまして、中身をぽろり。酔った二人は気づかねえ。
拾い直したその樽にゃ、道端で酔いつぶれて寝ていた**願人坊主**が入っておりました。

火屋の窯の前、熱さに目を覚ました坊主が一声——

坊主「あちちち! ……おい、ここはどこだ!」

火屋の番人「どこもこうもあるかい、**火屋(ひや)**よ!」

坊主「ひや? ——**冷やでいいから、もう一杯**」

お後がよろしいようで。
